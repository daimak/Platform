# 1. Three-Level Interface Model

Estate должен разделять три разных режима взаимодействия.

## Level 1 — Estate World

Визуальный мир eVo.

Отвечает на вопрос:

> Где и что происходит?

Содержит:

- острова;
- здания;
- Бэрримора;
- корабли;
- природные элементы;
- визуальные события;
- внешние архипелаги в будущем.

Estate не должен превращаться в обычный dashboard.

Он является пространственной визуальной моделью системы.

---

# 2. Level 2 — Command Center

Главная панель управления Estate.

Основной вход — Бэрримор.

Отвечает на вопрос:

> Что сейчас происходит в моей системе в целом?

При клике на информационное окно Бэрримора открывается большая панель поверх Estate, при этом сам мир остаётся видимым вокруг.

В Command Center могут находиться:

- активные задачи;
- события;
- входящие сообщения;
- состояние системы;
- память;
- состояние подсистем;
- краткая сводка;
- навигация;
- другие элементы общего управления.

Command Center не является рабочим местом для детального выполнения задачи.

---

# 3. Level 3 — Workspace / Рабочий кабинет

Отдельный режим для непосредственной работы.

Отвечает на вопрос:

> Что конкретно я сейчас делаю?

Примеры:

- редактирование задачи;
- изменение статуса;
- работа с контекстом;
- документы;
- чек-листы;
- результаты;
- инструменты;
- конкретные действия по задаче.

Workspace не обязан сохранять визуальную метафору Estate.

Это может быть полноценный плотный рабочий интерфейс.

Переход:

Estate / Command Center
        ↓
🚪 Перейти в рабочий кабинет
        ↓
Workspace

Возврат:

Workspace
        ↓
← Вернуться в Estate
        ↓
Estate

---

# 4. Barrymore

Бэрримор является одним из важнейших элементов интерфейса.

Его нельзя проектировать просто как ещё одно здание.

Он является точкой входа в Command Center.

## Default state

Небольшое полупрозрачное информационное окно:

- имя Бэрримора;
- количество активных задач;
- минимальная информация о состоянии.

## Hover state

При наведении мыши окно плавно расширяется.

Показывает:

- количество активных задач;
- задачи, требующие внимания;
- заголовки последних / важных задач;
- короткий фрагмент текста задачи;
- другие важные элементы сводки.

Длинный текст должен ограничиваться по количеству строк.

Hover не должен закрывать окно при перемещении курсора с Бэрримора на само информационное окно.

Персонаж и его информационное окно должны рассматриваться как единая интерактивная область.

## Click

Клик по информационному окну открывает Command Center поверх Estate.

## Workspace transition

В Command Center должна присутствовать отдельная визуальная точка перехода:

🚪 Перейти в рабочий кабинет

Это не обычная кнопка навигации, а часть визуальной метафоры Estate.

Клик переводит пользователя из Command Center в конкретный Workspace.

---

# 5. Buildings

Здания являются специализированными функциональными объектами.

Каждое здание должно иметь:

- визуальный asset;
- интерактивную область;
- название;
- описание;
- количество активных процессов;
- hover state;
- click state;
- собственный функциональный интерфейс.

Здание отвечает на вопрос:

> Что делает эта часть системы?

В отличие от Бэрримора, здание является специализированным рабочим объектом.

---

# 6. Visual / UI Separation

Растровая графика:

- здания;
- острова;
- декоративные элементы;
- море;
- природные объекты;
- художественные таблички / рамки.

HTML / CSS / application layer:

- текст;
- названия;
- количества;
- статусы;
- задачи;
- меню;
- hover states;
- интерактивность;
- функциональные панели.

Текст не должен зависеть от качества масштабирования исходного изображения.

Если в художественной графике присутствует табличка, по возможности сохраняется её визуальная форма, а содержимое выводится отдельным HTML/CSS-слоем.

---

# 7. Important Design Principle

Estate не должен становиться dashboard.

Command Center не должен становиться Workspace.

Workspace не должен пытаться изображать Estate.

Каждый уровень должен иметь собственную задачу:

Estate
→ визуальная модель мира

Command Center
→ управление миром

Workspace
→ непосредственная работа

---

# 8. Priority

Высокий приоритет.

Первый практический прототип:

1. Одно обычное здание:
   - отдельный PNG;
   - hover;
   - информационное окно;
   - click;
   - функциональная панель.

2. Бэрримор:
   - отдельный интерактивный объект;
   - collapsed info window;
   - динамическое расширение при hover;
   - click → Command Center;
   - Command Center → Workspace через визуальную "дверь".

3. Только после этого расширять модель на остальные здания.
