# Архитектурные принципы eVo

## Разделение ответственности

Платформа разделяется на:

- Core — ядро системы.
- Modules — функциональные расширения.
- Interface — способы взаимодействия.
- eVo — интеллектуальная логика.
- Memory — внутренняя память системы.
- Workspace — данные пользователя.

## Правила

1. Core не зависит от Interface.
2. Modules используют Core.
3. eVo использует Core, Modules и Memory.
4. Workspace принадлежит пользователю.
5. Memory принадлежит системе.
6. Каждый компонент должен иметь понятное назначение.

---

## Принцип автоматизации действий

Пользователь не должен выполнять длинные последовательности технических операций вручную.

eVo должен преобразовывать сложные процедуры в простые действия, которые можно выполнить одной командой.

Пример:

`evo-save`

Одна команда должна скрывать внутреннюю последовательность операций:

- проверка состояния проекта;
- анализ изменений;
- фиксация контекста;
- сохранение версии;
- синхронизация.

Главная идея:

> Пользователь управляет намерением. eVo управляет процедурой.
