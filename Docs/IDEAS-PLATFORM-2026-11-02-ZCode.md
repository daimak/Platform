## А. Деньги и работа (топ-приоритет — закрывает «жутко важно» Дмитрия)

**1. Конвейер откликов (Proposal Pipeline).** Уже есть 12 драфтов (лейн 1). Добавить: tracking-таблицу откликов (заказ → статус → ответ → follow-up) в лиджер/канбан + правило «каждое утро 3 отклика из очереди Хантера». `База:` Workspace/private/proposals/, доска Хантера. `Метрика:` ≥10 откликов/нед, доля ответов.

**2. Радар денег v2 — живой, а не по прогону.** Telegram-каналы заказов читать ботом (polling при ручном запуске), новые заказы с фильтром «скраперы/боты» — вспышка на дашборде. `База:` tools/job_search.py (TG-источник уже есть), радар. `Метрика:` время от публикации заказа до появления на радаре <15 мин.

**3. Калькулятор ставки.** По накопленным снапшотам вакансий считать медианную вилку по категории/стаку и подсказывать ставку при отклике. `База:` salary_extracted.csv + orders_board.json (19 вилок, медиана $10k — уже посчитано). `Метрика:` каждая заявка с обоснованной ставкой.

**4. Portfolio-as-Code: витрина скраперов.** 2-3 мини-демо (скрапер → красивый отчёт/дашборд) на легальных мишенях, публичная страница-визитка БЕЗ интерьера платформы (правило видимости) — ссылка в откликах. `База:` olx_production.py (каскад 94.5%), job_search.py. `Метрика:` упоминание демо в откликах → конверсия в ответы.

**5. Симулятор недели (что-если).** «Сколько денег при N откликах/день с конверсией X» — простая табличка-калькулятор в Trading Quarter из данных радара. `База:` orders_report.md. `Метрика:` используется при планировании недели.

**6. Follow-up бот.** Напоминания «отклик висит 3 дня без ответа → черновик follow-up» — детерминированный скрипт над tracking-таблицей (из идеи 1). `Метрика:` ни один отклик не забыт >5 дней.

## Б. Агентный штат (продолжение агентной инициативы)

**7. Оформить «Ночного сторожа» как сотрудника.** Родился сегодня сам: cron-пинг + STATE-NIGHT + QUEUE. Дать паспорт, метрику («ни один лейн не брошен; потеря при сбое ≤ 1 каданса») и строку в штат v4. `База:` Workspace/reports/night-2026-11-02/. `Метрика:` утренний отчёт насоса без потерь.

**8. Хантер v2 — санкционированный патруль.** Разрешить Хантеру (по кнопке) прогонять источники и готовить дифф «что нового с прошлого прогона», вместо полного свода. `База:` tools/hunter/report.py. `Метрика:` время подготовки доклада <2 мин.

**9. Квотермейн — оценщик добычи.** LLM-скоринг доски: каждая находка получает score (деньги × вероятность × соответствие навыкам), топ-10 на радаре с обоснованием. `База:` паспорт-концепт, skill research-synthesist. `Метрика:` топ-10 скоринга совпадает с выбором Дмитрия в ≥70%.

**10. Оживить Аналитика (кандидат в штате с 30.10).** Поле ввода на дашборде: «сумбурный вопрос» → Аналитик раскладывает на задачи и раскидывает по островам/агентам (черновик задач — по санкции). `База:` задача в штате, паспорт-шаблон. `Метрика:` 3 вопроса/нед превращаются в задачи.

**11. Risk scan — рантайм на шлюзе.** Единственный сотрудник без рантайма: переписать прогон по образцу run_agent.py (шлюз :31415 не жжёт план) и вернуть в цикл кнопки «Прогон». `База:` automations_backup, run_agent.py. `Метрика:` риск-отчёт на каждую порцию правок.

**12. Полный цикл поводка: одна кнопка.** «Прогон» = Холмс → Risk scan → Бэрримор-сводка с графой «результат в кармане». Все рантаймы уже есть/готовятся — остаётся склеить. `База:` E-028…E-031 наработки. `Метрика:` 1 клик → 1 сводка ≤ 5 мин.

## В. Дашборд и интерфейс

**13. Панель утра.** Первое окно дашборда: что произошло ночью (сводка насоса из QUEUE/STATE) + digest Хантера + новые задачи. Утром одним взглядом. `База:` morning brief + STATE-NIGHT. `Метрика:` Дмитрий читает бриф ежедневно.

**14. Виджет токен-метра.** График расхода по дням/сессиям из ledger.jsonl прямо в дашборде + пороговые алерты. `База:` Workspace/analytics/token-spend/ledger.jsonl. `Метрика:` решение о «прожиге/экономии» принимается по графику, не по ощущениям.

**15. Кабинет Хантера на живых данных.** Кабинет в engine-core показывает очередь — связать с digest.json: вилка/категория/скоринг, кнопка «Обновить доклад» (запуск report.py). `База:` hunter-report.js, /api/hunter/tasks. `Метрика:` доклад обновляется без консоли.

**16. Канбан v3: просрочки и фильтры.** Подсветка просроченных due, фильтр по owner/priority, счётчик «старше 7 дней». `База:` kanban.js (pointer-drag, модалка). `Метрика:` ноль забытых задач.

**17. PWA/мобильный вид.** Дашборд с телефона: бриф + радар + канбан только для чтения. `База:` статический дашборд, loopback → нужен проброс/VPN (обдумать видимость!). `Метрика:` доступ с телефона к радару.

**18. Живая карта архипелага.** Острова подсвечиваются по реальному состоянию: Harbor — активность внешних запросов, Observatory — свежесть digest, Workshop — dirty-файлы, Holmes Study — дата аудита. Карта = healthcheck. `База:` healthcheck.py, languages.js islands. `Метрика:` карта отвечает на вопрос «где болит» без логов.
