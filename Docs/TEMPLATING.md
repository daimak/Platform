# Протокол шаблонизации приватных координат (Docs/TEMPLATING.md)

**Дата:** 2026-11-07 · **Журнал:** E-053 · **Статус:** действующий протокол

## Зачем

Инфраструктурные координаты поместья (IP ВМ, имена облаков, локальные ключи) не должны
жить ни в git (репо публичное), ни «в памяти сессий» (умирает вместе с разговором).
Решение — ansible-подобное разделение: **шаблон в git + приватные переменные вне git +
рендер одной командой**.

## Структура

| Путь | В git? | Роль |
|---|---|---|
| `templates/*.j2` | ✅ | источник правды; `{{ имя_переменной }}` вместо значений |
| `Workspace/private/vars/*.json` | ❌ (весь `Workspace/private/` игнорируется) | реальные координаты, **per-host** |
| `Docs/generated/` | ❌ | отрендеренные доки с реальными значениями — читать здесь |
| `Docs/*.md` (отрендеренные) | ✅ | repo-артефакт с `<плейсхолдерами>` — публичная версия |
| `tools/render_templates.py` | ✅ | рендерер (Jinja2) |

## Команды

```bash
# личная версия с реальными координатами -> Docs/generated/
python tools/render_templates.py

# repo-версия (плейсхолдеры) — то, что коммитим
python tools/render_templates.py --repo

# один шаблон в конкретное место
python tools/render_templates.py templates/cloud-vm-runbook.md.j2 \
  --out Docs/CLOUD-VM-RUNBOOK-2026-11-07-ZCode.md --repo
```

## Правила

1. **Отсутствующая переменная = `<имя>`, не ошибка.** Repo-артефакт собирается даже без
   приватных данных, и случайно утечь он не может: repo-режим (`--repo`) подставляет
   плейсхолдеры даже если переменные на месте (покрыто тестом `test_no_secret_leak_in_repo_mode`).
2. **Переменные per-host.** Между машинами git-ом не переносятся; каждая машина ведёт свой
   `Workspace/private/vars/`. Секреты-КЛЮЧИ сюда не кладём — им место в Vault
   (C:/Users/temp/Vault), vars — только координаты и параметры.
3. **Правки — в шаблон.** Файл в `Docs/` с пометкой «генерируется» руками не правится:
   правим `templates/*.j2`, перерендериваем, коммитим repo-версию.
4. **Именование переменных:** плоский snake_case, файлы vars — по теме
   (`cloud-vm.json`, дальше — например `vitrina.json`).
5. Слияние файлов — по алфавиту, поздний файл перетирает ранний (см. тесты).
