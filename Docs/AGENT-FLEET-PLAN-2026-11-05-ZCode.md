# ТЗ: «Флот в море» — дашборд запущенных агентов

Создано: 2026-11-05 ZCode · Идея и заказ: Sovereign («хочу дашборд по запущенным агентам, отвал башки»)
Карточка: канбан `agents-fleet`. Статус: ждёт сдачи data-foundation (нужны конверт Л-1 и events.jsonl Л-2).

## Зачем

Агенты работают невидимо: у ZCode-суб-агентов нет окна в UI, статус знает только ZCode-через-раз; штатные (Холмс/Хантер) пишут в свои углы. Панель делает каждый запуск видимым от постановки до итога. Метафора мира: агент = корабль в море поместья, задача = рейс.

## Принцип: панель — читатель, а не писатель

Единственный источник данных — `Workspace/logs/events.jsonl` (лейн Л-2 data-foundation) с конвертом Л-1. Панель не собирает ничего сама. Кто не пишет события — для панели не существует. Фаза 2 (отдельная задача): врезки маячков в рантаймы штатных (Холмс, Хантер).

## События агентов

`schema_id="evo.agent.event"`, поле `by` = имя корабля («Строитель-1», «Верификатор», «Холмс»). Виды (`payload.kind`):

- `agent.started` — рейс начался: задача, путь к ТЗ, список лейнов, оценка токенов/времени. → **начальные**
- `agent.lane` — закрыт лейн: какие файлы, тесты зелёные. → **промежуточные**
- `agent.pulse` — маячок жизни (любая заметная веха, «коптил небо N минут»).
- `agent.storm` — шторм: ретрай, concurrency-ошибка, падение. → **промежуточные**
- `agent.finished` — рейс завершён: вердикт (принято/доработка), итоговый список файлов, тесты, факт токенов/времени. → **итоговые**

## Метрики панели

Фактические: лейны done/total; время в море; число штормов; минуты с последнего события.
Экстраполированные (панель помечает значком «~» и легендой «оценка»): ETA рейса (по фактической скорости лейнов); токены (оценка от started-записи); статус пульса: «идёт» (<10 мин с события) / «тихо» (10–30) / «шторм» (storm-событие или >30 мин тишины).

## API (малые вставки в dashboard-server.py)

- `GET /api/agents/live` — текущие рейсы: `[{by, task, status(море|причал|шторм), lanes:{done,total}, pulse_min, storms, started_at, eta_min, events_recent:[5]}]`.
- `GET /api/agents/history?limit=20` — завершённые рейсы с итогами.

## UI

`eVo/dashboard/agents.html` + `agents.css` + `agents.js?v=1` — «Флот в море»:

- Секция «В море»: карточка-корабль на каждый активный `by` — парус/пульс-анимация, шкала лейнов, лента последних чекпоинтов, значок шторма, таймер и ETA.
- Секция «Причалы»: завершённые рейсы — цепочка «начальные → промежуточные → итоговые» в одну строку на рейс.
- Стиль — как у основного дашборда (тёмный, ватерлиния, без чёрных полос). Автообновление каждые 15 с (fetch), кнопка «Обновить сейчас».
- Опционально вторым шагом: бейдж на карте Estate «кораблей в море: N».

## НЕ делать (фаза 1)

- Управление агентами с панели (спавн/останов) — только наблюдение.
- Прямое чтение model-io/*.jsonl и транскриптов суб-агентов — токены только оценкой.
- Логины, роли, графики — сырой тест.

## Кто и когда

Строит суб-агент ZCode (паттерн data-foundation) ПОСЛЕ сдачи Лейнов — во-первых, нужен events.jsonl, во-вторых, параллельные рейсы бьются о concurrency-лимит провайдера. Первый рейс с полным протоколом маячков — сам строитель панели (его стартовая запись, лейн-маячки и итоговая верификация ZCode станут живыми данными для отладки).
