## Выводы для очистки датасета

1. **Дедуплицировать по нормализованной паре (title, company), не по URL** — снимает 63 записи (213 → 150). URL гарантированно уникальны, а кросспостинги hh.ru/hh.uz живут на разных доменах (включая рекламные редиректы `adsrv.hh.uz`), так что URL-нормализация их не склеит.
2. **Отфильтровать по дате: 28 записей старше 30 дней**, в первую очередь архивировать весь канал TG @devops_vacancies (20 записей, кэш августа-сентября 2025). Для 123 записей hh/OLX без даты — либо доставать дату при загрузке, либо помечать `date=unknown` и не считать их «свежими».
3. **Salary добывать из трёх мест по приоритету:** (а) regex по title+snippet — даёт +8 записей (покрытие 3.8% → 7.5%), главный донор — HN; (б) у TG — парсить title (блок после 💰), но реально там только «По договорённости»; (в) для hh — только фетч страницы вакансии, в сниппете зарплаты нет.
4. **Вычистить шум:** 3 записи OLX.uz — не вакансии (мерч DevOpsDays, фриланс-гиг), snippet и company пустые; TG-записи — company содержит канал (`t.me/...`): реального работодателя парсить из title (блок между 🏢 и •) или хранить канал отдельно.
5. **Нормализовать поле salary** к структуре (min, max, валюта, период): сейчас в поле вперемешку «100000-140000 USD», «$170k - $200k», «$1000 per task», «200 000 сум» — регулярки из раздела ниже это покрывают.

## Готовые regex для salary-парсера (протестированы на всех 213 записях)

Python `re`, применяется к `title + "\n" + snippet` (R4–R5 — к полю salary). DASH = `[-–—]` (дефис, en-dash, em-dash — в данных встречаются все три).

| # | Regex | Что ловит | Совпадений на реальных данных |
|---|-------|-----------|-------------------------------|
| R1 | `\$\s?\d{1,3}(?:[.,]\d)?\s?[KkКк]\s*[-–—]\s*\$?\s?\d{1,3}(?:[.,]\d)?\s?[KkКк]\b` | диапазоны `$54K - $205K`, `$140K-$264K`, `$150k–$260k` | **6 записей / 7 вхождений** (5 HN + 1 TG) |
| R2 | `\$\s?\d{1,3}(?:[.,]\d)?\s?[KkКк]\b(?!\s*[-–—])` | одиночная `$170k`; применять ПОСЛЕ R1 — тогда ловит верхнюю границу диапазона | **6 записей / 7 вхождений** (на поле salary: 1 — Remotive `$170k - $200k`) |
| R3 | `\b\d{1,3}(?:,\d{3})+(?:\.\d+)?\s*[-–—]\s*\$?\s?\d{1,3}(?:,\d{3})+(?:\.\d+)?\s*(?:USD)?` | диапазон с разделителями-запятыми `$175,000 - $215,000 USD` | **1 запись / 1 вхождение** (HN) |
| R4 | `\b\d{4,7}\s*[-–—]\s*\d{4,7}\s*USD\b` | поле RemoteOK `100000-140000 USD` | **5 записей** (все RemoteOK-диапазоны поля salary); в title+snippet — 0 |
| R5 | `\d[\d\u00A0\u202F ,.]{2,}\s*сум` | `200 000 сум`, `15 000 000 сум` | **в title+snippet: 0**; в поле salary: 1 (OLX). Держать про запас для hh.uz/UZS-страниц |
| R6 | `\$\s?\d+(?:[.,]\d{1,2})?\s*[-–—]\s*\$?\s?\d+(?:[.,]\d{1,2})?\s*/\s*(?:hr\|час\|h)\b` | почасовые `$7.25–$10/hr` | **1 запись / 1 вхождение** (HN) |

Итог по union R1+R3+R6 (для title+snippet): **8 записей**, все с пустым полем salary. Ложных срабатываний не обнаружено (все примеры — реальные зарплатные строки). Опционально для HN-диапазонов без `$`: `\b\d{2,3}\s?[Kk]\s*[-–—]\s*\d{2,3}\s?[Kk]\b` — на текущих данных даёт 0 (HN-постеры пишут с `$`).
