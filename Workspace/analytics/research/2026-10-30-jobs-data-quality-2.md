## Выводы для очистки датасета
1. **Главная проблема — не URL-дубли, а повторы вакансий под разными URL**: 63 избыточные записи (~30%). Нужен dedup по нормализованной паре (title+company), а не по URL.
2. **Telegram @devops_vacancies удалять целиком**: все 20 записей старше 30 дней — мёртвый кэш. Плюс 4 устаревших записи из @remote_jobs_ru и 4 из RemoteOK. Итого 28 записей (13.1%) — кандидаты на удаление; ещё 123 (57.7%) требуют переполучения даты из HTML hh/OLX, иначе возраст невозможно оценить.
3. **Поле `company` у Telegram-источников требует исправления**: извлекать работодателя из title по маркеру «🏢», иначе аналитика по компаниям искажена на 16% датасета.
4. **Отфильтровать 2 не-вакансии** (мерч, фриланс-реклама) — признак: пустое company + отсутствие «🏢»/структуры.
5. **Salary-парсер по title+snippet удваивает покрытие зарплат** (с 8 до 16 записей, +3.7 п.п.) при нулевом уровне ложных срабатываний на этом датасете — см. готовые regex ниже. Все 8 непустых значений поля `salary` также покрываются этим набором паттернов (унификация форматов).
6. Датасет перекошен в сторону hh.ru/hh.uz (120 записей, 56%) без дат и зарплат в тексте — если salary-аналитика важна, hh-парсер нужно учить тянуть «зарплату вилкой» из HTML.

## Готовые regex для salary-парсера (протестированы на всех 213 записях + 8 значениях поля salary)

```python
# 1) Долларовые форматы: $54K - $205K | $175,000 - $215,000 | $140K-$264K |
#    $150k–$260k (en-dash) | $7.25–$10/hr | $170k - $200k | $1000 per task (голова)
# -> title+snippet: 8 записей; salary-поле: 2 значения ($1000, $170k - $200k). Ложных срабатываний: 0.
R_DOLLAR = re.compile(
    r'\$\s?\d{1,6}(?:,\d{3})*(?:\.\d{1,2})?(?:\s?[KkКк]\b)?'
    r'(?:\s?[-–—]\s?\$?\s?\d{1,6}(?:,\d{3})*(?:\.\d{1,2})?(?:\s?[KkКк]\b)?)?')

# 2) «100000-140000 USD» (без $): title+snippet: 0; salary-поле: 5/5 значений RemoteOK.
R_RANGE_USD = re.compile(r'\b\d{2,6}(?:[ ,]\d{3})*\s?[-–—]\s?\d{2,6}(?:[ ,]\d{3})*\s?(?:USD|usd)\b')

# 3) «200 000 сум» (пробел/nbsp как разделитель тысяч): title+snippet: 0; salary-поле: 1/1 (OLX.uz).
R_SUM = re.compile(r'\d{1,3}(?:[ \u00A0]\d{3})+\s?сум\b')

# 4) Ставка за единицу работы: «$1000 per task» (salary-поле: 1/1), «$10/hr» (title+snippet: 1, в составе $7.25–$10/hr).
R_PER_UNIT = re.compile(r'\$\s?\d{1,6}(?:\.\d{1,2})?\s?(?:per\s?|/\s?)(?:task|hour|hr|month|year|week|day|project)\b')
```

Примечания:
- В `R_DOLLAR` голова `\d{1,6}` обязательна: вариант `\d{1,3}` откусывает `$100` от `$1000` (проверено).
- Диапазоны в реальных данных используют `-`, `–` (en-dash) и `" - "` — класс `[-–—]` покрывает всё встреченное.
- Единственный формат USD-диапазона без `$` в датасете — «NNNNNN-NNNNNN USD», встречается только в поле `salary` (RemoteOK).
