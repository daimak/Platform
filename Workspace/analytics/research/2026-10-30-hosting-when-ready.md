## Вариант А — «зеркало дашборда» (read-only с телефона)

### Сравнение: GitHub Pages vs Cloudflare

| | GitHub Pages | Cloudflare Pages / Workers Static Assets |
|---|---|---|
| Приватный репозиторий | Только на платных планах (Pro ~$4/мес, Team, Enterprise) | Да, бесплатно |
| Приватный **сайт** | **Нет.** Сайт публичный, даже если репо приватный — нативной защиты нет | **Да, через Cloudflare Access** (Zero Trust): email OTP, до 50 пользователей бесплатно |
| Полоса | ~100 ГБ/мес soft limit | Не лимитирована (в рамках ToS: без раздачи видео/не-HTML тяжёлого контента) |
| Билды | 10/час soft | Pages: 500/мес (для снапшота 1–2 раза в день — с запасом ×10) |
| Размер | 1 ГБ сайт | 20 000 файлов/проект, 25 МБ на файл |
| Перспектива | Стабильно | **Pages — maintenance mode** (август 2025, нет новых фич); новые проекты Cloudflare рекомендует делать на **Workers + Static Assets**. Старые Pages-проекты работают, закрытия не объявлено |

**Вердикт:** для личного дашборда GitHub Pages не подходит в принципе (сайт всегда публичный). Cloudflare выигрывает вдвойне: бесплатно + Access как пароль-защита. Для нового проекта идти сразу на **Workers + Static Assets** (или Pages, если удобен Git-connect, — тоже рабочий вариант на годы).

### Цена
- **0 $/мес**: Pages/Workers free + Access free (до 50 пользователей) + аккаунты.
- 0 $, если не покупать домен (`*.pages.dev` / `*.workers.dev` достаточно для зеркала).

### Шаги (реалистичный план)
1. Локально: скрипт-«снапшоттер» на Python — рендерит статический HTML дашборда с вмороженными данными (JSON, зашитый в страницу или рядом). Никакого `/api` — зеркало строго read-only.
2. Развёртывание: `wrangler deploy` (папка статики в `assets`) — или Git-connect на Pages. Снапшот = деплой (1–2 раза в день вручную или позже из Actions/VPS).
3. Zero Trust → Access → создать приложение на домен зеркала (работает и на `*.pages.dev`), политика: allow `твой@email` через One-Time PIN. С телефона: открываешь URL, вводишь email, получаешь код.
4. Ничего секретного в статику не кладём: данные дашборда — не секреты, но при желании Access закрывает и их.

### Лимиты, о которых помнить
- Access free: 50 пользователей, email OTP без настройки IdP; нет SSO-фишек платных планов.
- 500 билдов/мес на Pages free (Workers free лимита билдов не имеет — деплой прямой).
- Access-защита не работает «в обход»: статику всё равно не следует считать секретной на 100 % (кэш/CDN-узлы). Секреты — только в `.env`/хранилище, не в статику.

### Рекомендация по выбору
1. **Сначала попробовать Oracle Free** (Дубай как home region): 0 $ за 4 vCPU/24 ГБ — дешевле не бывает. Риск: capacity-рулетка и подводные камни регистрации.
2. **Fallback — Hetzner CAX11** (ARM, 4 ГБ): Docker на ARM64 сегодня без проблем (python-образы мультиарх). ~8 €/мес брутто — потолок бюджета.

### Шаги (когда триггер наступит)
1. VPS: Ubuntu LTS → `apt install docker.io docker-compose-plugin` (или Docker CE из официального репо).
2. Архитектура: **на VPS живёт только рантайм скраперов/агентов**, а НЕ публичный `/api` сервер. ПК и после переезда остаётся loopback-only.
3. Результаты скрапинга везти в дашборд одним из способов: git push снапшотов в приватное репо → автодеплой зеркала (Вариант А); или rsync/scp на ПК по Tailscale/WireGuard; или S3-совместимое хранилище (CF R2 free: 10 ГБ).
4. Расписание: cron внутри VPS (`crontab`) для контейнерных задач; GitHub Actions cron как дешёвый старт ДО покупки VPS (см. ниже).
5. Мониторинг: healthcheck-URL + внешний пингер (например, CF Workers Cron «пиналка» раз в час → уведомление в Telegram-бот).

### Docker-заметки
- База: `python:3.12-slim`, мультиарх (работает и на ARM Hetzner CAX, и на Oracle A1). Зависимости — `requirements.txt` / `uv`; тяжёлым C-пакетам (lxml и т.п.) на ARM норм, они есть в wheels.
- `restart: unless-stopped` в compose; логи — `json-file` с ротацией (`max-size: 10m`), иначе диск переполнится.
- Секреты: **не печь в образ**. `env_file: .env` на хосте (файл вне git) или Docker secrets; `.dockerignore` с `.env`; сборку на CI — только без секретов, либо сборка на самом VPS.
- Наружу не открывать порты вообще: SSH + WireGuard/Tailscale для себя, исходящий HTTPS для скраперов. Публичный HTTPS для админки (если понадобится) — через Cloudflare Tunnel, а не port forwarding.
- Харденинг VPS: SSH только по ключам (`PasswordAuthentication no`), `ufw default deny incoming`, fail2ban, `unattended-upgrades`, отдельный не-root пользователь.
- Бэкапы: `restic`/`borg` по cron в зашифрованном виде (возраст-ключ) на другой end (например, R2), раз в неделю тест восстановления.

### Scheduled-задачи БЕЗ полного сервера
| Способ | Лимиты | Годность для Python-скраперов |
|---|---|---|
| **GitHub Actions cron** | Мин. интервал 5 мин; **запуск не гарантирован вовремя** — при пиках задержки минутами/часами, запуски могут дропаться; job ≤ 6 ч; **public repo: минуты бесплатны и безлимитны; private repo: 2000 мин/мес** на Free (Pro $4/мес → 3000 мин) | **Да — лучший бесплатный старт.** 2–4 запуска/день × 5–10 мин = 300–1200 мин/мес — влезает даже в private-free. Секреты — через Actions Secrets, не в код |
| **CF Workers Cron Triggers** | Free: 100 000 req/день на воркеры, **3 cron-триггера на Worker** (в разных источниках ~5 на аккаунт free), мин. интервал 1 мин, **нет автоповторов и алертов о падении**; язык — JS/WASM (Python = Pyodide beta: pip-пакеты с C-расширениями не заведутся) | Для самих скраперов — **нет**. Годится как HTTP-«пиналка»/триггер/монитор чужих эндпоинтов |
| systemd timers / cron на VPS | — | Основной способ, когда Вариант Б развёрнут |

Промежуточный вывод: до покупки VPS скраперы можно гонять в GitHub Actions по cron (private repo, 2000 мин free), а материалы складывать в репо/артефакты — это репетиция Варианта Б за 0 $.

## Вариант В — «портфолио» (DevOps-профиль)

- **Хостинг:** CF Pages/Workers, **отдельный публичный проект** (без Access!), можно Git-connect из публичного репо. $0/мес.
- GitHub Pages тоже годится (портфолио по определению публичное): 1 ГБ / 100 ГБ-мес / 10 билдов-час — с головой; плюс привычная экосистема. Но если домен всё равно на Cloudflare — держать всё в одном месте проще.
- **Домен:** ~$10/год (.com/.dev/.me), HTTPS бесплатно (Let's Encrypt авто / CF Universal SSL).
- **Контент для DevOps-профиля:** сам этот репозиторий как кейс (архитектура Platform Evo: stdlib-сервер без зависимостей, loopback-only security model, secrets-гигиена, CI для снапшотов), публичный README с диаграммами; зеркало дашборда как живое демо (закрытое Access — скриншоты в портфолио).
- Кастомный домен + авто-HTTPS — 10 минут в панели CF.

## Security-чеклист перед переездом (обязательные преграды)

**Секреты / .env:**
1. Инвентаризация: выписать всё из `.env` (ключи LLM, API скраперов, токены) и понять blast radius утечки каждого.
2. Проверить, что `.env` в `.gitignore` и **никогда не попадал в git-историю**; если попадал — считать скомпрометированным и ротировать.
3. **Ротация всех ключей** накануне переезда: серверу — новые ключи, старые — отозвать/сузить.
4. У LLM-провайдеров: spending limits/бюджетные алерты, отдельный ключ для сервера и для локалки, чтобы компрометация одного не опустошала счёт.
5. **Мастер-хранилище:** KeePassXC (офлайн-файл — ноль серверов, идеальный первый шаг) или Bitwarden/Vaultwarden. Туда: мастер-пароль от бэкапа `.env`, SSH-ключи, токены провайдеров. Мастер-пароль — длинный, уникальный, нигде не повторяется.
6. Опционально «секреты как код»: **SOPS + age** — в репо лежит `.env` с зашифрованными значениями (ключи в plaintext — читаемые diff'ы), age-ключ живёт ТОЛЬКО в хранилище/на устройствах, не в репо. Это правильный формат, когда конфиги переезжают между машинами/VPS.
7. Бэкап `.env`-эквивалента — зашифрованный (age) и не на том же диске, что и рабочая копия.

**При переезде на VPS (Вариант Б):**
8. SSH: только ключи, без пароля; root-login `prohibit-password`; fail2ban; ufw default deny; unattended-upgrades.
9. Порты наружу не открывать: WireGuard/Tailscale для администрирования, Cloudflare Tunnel — если понадобится публичный HTTPS.
10. Docker: `.env` вне образов (env_file на хосте / secrets), `.dockerignore` содержит `.env`, пуш образов с секретами — запрещён; логи с ротацией.
11. Данные, которые едут на VPS, минимизировать: серверу нужны ключи скраперов, но не весь `.env` домашней платформы.
12. После переезда: проверить, что домашний ПК по-прежнему не слушает ничего кроме loopback (`netstat -an | findstr LISTENING`), и что зеркала/CI не содержат секретов.
