## ПРЯМО СЕЙЧАС (выполнить сегодня)

### 1. `python tools/ops/backup_workspace.py`

**Что:** копирует незакоммиченное (`M` + `??` из git status) в `%LOCALAPPDATA%\Platform\Backups\<дата-время>\` с сохранением путей.
**Зачем:** в дереве сейчас лежат незащищённые результаты: hand-правленный `brief.js` (его перезапишет первый же refresh брифа), парсер `tools/autoservices_search.py` с данными, `TOKEN_USAGE_LOG.md`. Один сбой — и их нет. `graphify-out/` (кэш) пропускается.
**Восстановление:** вручную переписать файлы из каталога копии обратно.

### 2. `python tools/ops/healthcheck.py`

**Что:** читающая проверка здоровья по находкам аудита: целостность `brief.js` (F1), валидность каждой задачи в `Memory/Engineering/Tasks/Active/` (F2), журнал AI-Usage (F4), живость дашборд-сервера `127.0.0.1:8765` + `GET /api/tasks`, allowlist `security-targets.json`, очередь Hunter, наличие `Workspace/.env` и `FREE_LLM_API_KEY` (только факт — значение не читается), отставание git от origin.
**Зачем:** детекторы находок аудита. `FAIL` = нужно действие; `WARN` = известная ситуация. Годится для прогона руками или по расписанию.

## АНАЛИТИКА ПОИСКА РАБОТЫ (шаги 1–2, готовы 2026-10-30)

Лежат рядом с `tools/analytics_snapshot.py`, тот же стандарт (stdlib-only, cache, dry-run).

### Шаг 1. `python tools/analytics_salary_extract.py [--apply]`

**Что:** достаёт зарплаты из title/snippet вакансий снапшота через LLM-шлюз FreeLLMAPI (чанки по 30, кэш по idx — повторный запуск доэкстрагивает только недостающее), пишет `salary_extracted.csv` в каталог снапшота, нормализует в USD/месяц (`year/12`, `day*22`, `hour*160`; UZS через `--uzs-rate 12700` — **приближение**, курс не тянется из сети). Вызов логируется в AI-Usage (purpose=`Analytics salary extraction`).
**Факт первого прогона (2026-10-29):** 205 записей → модель нашла зарплату в тексте у 8 (плюс 8 уже было в jobs.csv). Остальные 197 — зарплаты в тексте **реально нет**: у hh (120 шт = 56% данных) она в отдельном поле выдачи, которое скрапер не берёт. **Главный следующий шаг парсера: брать salary у hh и price у OLX из структурных полей** — промптом это не чинится.

### Шаг 2. `python tools/analytics_report.py`

**Что:** одностраничный `report.md` в каталоге свежайшего снапшота: сводка + дифф с предыдущим днём (по URL), зарплаты по сегментам (remote-intl / tg-ru / tg-devops / hh-uz / hh-ru / olx) с медианой и p25/p75, таблица источников со свежестью, топ-10 «скорость до денег» (эвристика), OLX-сводка, честный блок ограничений.
**Ритм:** ежедневный прогон снапшота → extract (только новые) → report. Со второй пары точек появится дифф, через 1–2 недели — тренды.
**Правило учёта (решение Sovereign, 2026-10-30):** записываем ВСЁ, с зарплатой и без. Колонка `has_salary` (yes/no) в `salary_extracted.csv` — галочка для фильтрации; в отчёте секции «с ЗП ✓» и «Свежие без вилки — спросить ЗП при контакте». Отсутствие вилки — не красный флаг: вилку спрашиваем при первом контакте.

**Чего сознательно НЕ делаем:** BI-стек, базы данных, отдельный дашборд — пока отчёт не станет «читаю ежедневно». Если захочется SQL по CSV — DuckDB (один бинарник).
