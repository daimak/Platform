**Серьёзное (техдолг, не эксплуатируется сейчас):**
- **XSS-склонный innerHTML-пайплайн, строки 139–155 (`cardHTML`)**: `a.report`, `a.name`, `a.role`, `a.emoji`, `n.label`, `n.value`, `a.next` интерполируются в `innerHTML` без экранирования (строки 145–148, 150–154). Источник — first-party `standup-data.json`, поэтому сегодня это не дыра, а привычка. Но страница претендует на публичный стандарт, а регенератор JSON может когда-нибудь протащить пользовательский текст (цитата из кворка, отклик). Рецепт: escapeHTML-хелпер перед каждой интерполяцией. Статус: техдолг, коммитить можно, чинить — при первой правке файла.

**Мелочи:**
- **Гонка в `tick()` (строки 195–203)**: `setInterval(tick, 4000)` без in-flight guard — ответ дольше 4 с → наложение тиков, двойной `render(d)`; сравнение `JSON.stringify(d) !== prev` у параллельных тиков не атомарно. Практически benign (render идемпотентен, дифф по сигнатуре карточек аккуратный), но паттерн стоит пометить на будущее: `let busy` флаг или отмена предыдущего тика.
- **Тихий `catch(e){}` (строка 200)**: полузаписанный JSON или сбой fetch глотается молча — страница молча стареет, без какого-либо индикатора. Для протокола закрытого заседания некритично (phase=closed, данные стабильны), но хотя бы console.warn — дешёвая страховка.
- **Деление на ноль (строка 188)**: `100*done/cards.length` при пустом `agents` даёт NaN% ширины прогресс-бара. Edge case, не воспроизводится на текущих данных (7 агентов).

**Логика верна:** дифф-рендер по сигнатуре карточек сохраняет выделение текста; фаза «СЕАНС ЗАКРЫТ» берётся из `meta.phase` (в данных — `closed`, ключи `chair_speech.open/current/close` все на месте — «undefined» не всплывёт).

#### 3.2 P1-2: Origin-гейт POST-403 — ЖИВ

**Механика:**
- Бэк `tools/barrymore/dashboard-server.py`, **строки 929–941**: каждый POST требует заголовок `Origin` (строки 930–932: нет Origin → 403 «Запрос должен исходить из локального дашборда») и `parsed_origin.netloc.casefold() == Host` (строки 939–941: иначе 403 «Обновление разрешено только из локального дашборда»).
- Гейт `tools/barrymore/auth_gate.py`, `proxy()`, **строки 240–241**: при проксировании вырезаются `host, cookie, origin, referer, connection, content-length` — **Origin умирает на двери**.
- Для admin/agent (строки 423–426) POST уходит на бэк с `host_override=CFG['backend_host']` (Host бэка — 127.0.0.1:8765), но Origin уже пуст → бэк отвечает 403. Канбан-приёмка рейсов (POST /api/voyages/verdict), Правление (POST /api/council/*, whitelist строки 906–912, диспут 981+) и прочие кнопки за дверью мертвы. Новые council-POST ночи идут через тот же Origin-чек — через дверь они тоже 403.
- Гость POST и так отсечён (`read-only`, строка 445) — не пострадает.

**ТЗ вариант A (рекомендую: гейт-сайд, CSRF-граница не ослабляется для прямых локальных клиентов):**
- Файл `tools/barrymore/auth_gate.py`, `proxy()` строки 237–253: не выбрасывать Origin, а **реконструировать** его под Host, который увидит бэк. Конкретно: убрать `'origin'` из кортежа удаления (строка 240) и после `fwd['Host'] = ...` (строка 242) добавить `fwd['Origin'] = 'http://' + (host_override or u.netloc)` — бэк видит Origin == Host, схема http (бэк требует именно http, строка 939). referer оставить в удалении.
- Параметр передавать через `_proxy_pass` (строки 316–330) флагом, чтобы реконструкция шла **только для аутентифицированных** (admin/agent/member-GET) веток; login/register/face-ветки не трогать.
- Обоснование безопасности: SameSite=Lax + HttpOnly сессия гейта уже отсекает кросс-сайтовый POST; реконструкция Origin за аутентифицированной дверью CSRF не открывает.
- Верификация: под agent-сессией POST /api/voyages/verdict через гейт → 200 (а не 403); POST без сессии → 401; POST с чужим Origin из браузера без сессии — 401; локальный POST напрямую на бэк (мимо гейта) с отсутствующим Origin → по-прежнему 403.

**ТЗ вариант B (альтернатива, бэк-сайд; решение за CEO — как и стояло на стендапе):**
- Файл `tools/barrymore/dashboard-server.py`, строки 929–941: пропускать Origin-чек для запросов с заголовком `X-Evo-Role` (его ставит только гейт, строки 316–318 auth_gate.py) — доказательство «прошёл дверь». Минус: любой локальный процесс может подделать заголовок; но бэк и так доступен локальным процессам напрямую (loopback), так что граница не ослабляется, лишь декоративность Origin-чека за дверью признаётся явно.
