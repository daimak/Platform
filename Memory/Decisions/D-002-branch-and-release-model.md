# Decision D-002 — Модель веток и релизов

Дата: 2026-10-25
Статус: Принято (сформулировано пользователем)

## Context

D-001 (main + experiment) устарел: в репозитории накопилось 6 веток, фактическая работа шла в `release/v1.8.1`, а версии в документах расходились (v0.1 / 0.2 / 0.1.0-alpha / v1.8.1).

## Decision

- `develop` — основная активно развиваемая ветка.
- Работа над фичей ведётся в отдельной ветке задачи.
- Завершённая и работающая фича — повод для minor release: ветка задачи сливается в `feature_X.Y.Z`, затем `feature_X.Y.Z` → `develop`, затем `develop` → `release_X.Y.Z`.
- Версия системы определяется линией релизов; текущая линия — 1.8.x, следующий релиз — 1.8.2.
- Цель на будущее: релиз по факту готовой фичи («запилили, хорошо работает — делаем minor release»), без субъективного «чувствуем, что пора».

## Reason

Простая и предсказуемая модель для одного разработчика: одна активная линия (develop), явные точки стабилизации (release), номер версии отражает реальный прогресс.

## Consequences

- Заменяет D-001 (D-001 сохраняется как история).
- Противоречие с DECISION-0002 (semver «0.1.0-alpha») зафиксировано: точка отсчёта версий (0.x vs 1.8.x) требует отдельного решения.
- Первая ветка новой модели: `feature_1.8.2` (создана 2026-10-25 из `release/v1.8.1` после пуша последнего).
- Старые ветки (`experiment`, `test/gitops-001`, `develop` на origin, `refactor/platform-boundaries-v2`) после проверки слияния подлежат архивации/удалению — отдельное действие с подтверждением.
