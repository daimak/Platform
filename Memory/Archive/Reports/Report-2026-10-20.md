# Отчет о структуре проекта Platform

**Дата отчета**: 2026-10-20
**Цель**: Архитектурный аудит и фиксация структуры репозитория для обеспечения версионности и контроля изменений.

---

## 1. Общее назначение проекта
Проект **Platform** (eVo — Evolution Operating System) — это персональная система управления жизненной эволюцией. Архитектура ориентирована на сохранение контекста принятия решений, модульность и эволюционное развитие.

## 2. Основные компоненты и их назначение

| Каталог | Назначение |
| :--- | :--- |
| `Core/` | Ядро: принципы, архитектурные решения (ADR), глоссарий. |
| `Modules/` | Функциональные модули, независимые от ядра. |
| `Interface/` | Слои взаимодействия: Web-интерфейс на Vue 3/Vite. |
| `eVo/` | Интеллектуальный слой: планирование, анализ, дашборды, скрипты. |
| `Memory/` | Долговременная память: контекст, история сессий, хронология. |
| `Workspace/` | Рабочее пространство пользователя (проекты, артефакты). |
| `RFC/` | Предложения по развитию и принятые архитектурные решения. |
| `tools/` | Утилиты: автоматизация и ассистент выполнения `Barrymore`. |
| `Vision/` | Визуальное направление, концепты, идеи, сторителлинг. |
| `Docs/` | Системная документация: структура, принципы, решения. |

## 3. Ключевые архитектурные правила
- **Изоляция**: Ядро не зависит от интерфейса. Workspace и Memory принадлежат разным сущностям (Пользователь vs Система).
- **Продленная фиксация**: Каждое изменение должно сопровождаться ответом на вопрос "Почему это существует?".
- **MVP**: Реализация новых возможностей через минимально рабочие версии перед расширением.
- **История**: Вся эволюция должна быть наблюдаемой через Git и внутреннюю систему заметок (`Memory/`).

## 4. Комментарии и рекомендации
- **Версионность**: Данный отчет служит отправной точкой. Рекомендуется создавать подобные отчеты при значительных структурных изменениях (например, в конце каждого квартала или при смене версии платформы в `ARCHITECTURE.md`).
- **Связанность**: При добавлении новых модулей важно обновлять `Core/Glossary.md` и проверять соответствие принципам в `Core/Principles.md`.
- **Barrymore**: Инструмент `tools/barrymore/` является критическим узлом для аудита операций; следите за тем, чтобы все автоматизированные действия логировались согласно `TASK-PROTOCOL.md`.
