4. Estate как интерфейс
Estate НЕ должен превращаться в обычный dashboard.
У нас три уровня:
LEVEL 1 — Estate World
Визуальный мир.
Отвечает:
"Где и что происходит?"
Содержит:
- острова;
- здания;
- Barrymore;
- корабли;
- море;
- облака;
- природные элементы;
- визуальные события;
- позже внешние архипелаги.
LEVEL 2 — Command Center
Управление миром.
Открывается поверх Estate, при этом Estate остаётся видимым вокруг панели.
LEVEL 3 — Workspace
Конкретная рабочая среда.
Здесь пользователь уже непосредственно решает задачу, а не управляет визуальным миром.
Принцип:
Estate = визуальная модель мира
Command Center = управление миром
Workspace = непосредственная работа
Estate не должен становиться dashboard.
Command Center не должен становиться Workspace.
Workspace не должен пытаться изображать Estate.

5. Barrymore
Barrymore — один из важнейших элементов всей системы.
Его нельзя проектировать просто как ещё одно здание.
Он является точкой входа в Command Center.
План поведения:
DEFAULT:
Небольшое полупрозрачное информационное окно рядом с Barrymore.
Показывает:
- имя Barrymore;
- количество активных задач;
- минимальное состояние.
HOVER:
При наведении окно плавно расширяется динамически.
Показывает:
- количество активных задач;
- задачи, требующие внимания;
- заголовки важных/последних задач;
- короткий фрагмент текста задачи;
- другие важные элементы сводки.
Длинный текст должен быть ограничен по количеству строк.
Очень важно:
hover не должен закрывать окно, когда курсор перемещается с Barrymore на само информационное окно.
Barrymore + его окно должны рассматриваться как единая интерактивная область.
CLICK:
Клик по окну открывает Command Center поверх Estate.
В Command Center должна быть отдельная визуальная "дверь":
"Перейти в рабочий кабинет"
Это не просто обычная кнопка навигации.
Она должна быть частью визуальной метафоры Estate.
Клик переводит пользователя из Command Center в конкретный Workspace.

6. Здания
Вторая большая архитектурная идея:
Здание — не просто картинка.
Здание является специализированным функциональным объектом.
У здания должны быть:
- отдельный визуальный asset;
- интерактивная область;
- название;
- описание;
- количество активных процессов;
- hover state;
- click state;
- собственный функциональный интерфейс.
При наведении:
- здание слегка подсвечивается;
- появляется/расширяется информационное окно;
- пользователь понимает назначение объекта.
При клике:
открывается полноценная функциональная панель здания.
Например:
- создание задачи;
- изменение статуса;
- просмотр процессов;
- другие действия в зависимости от назначения здания.
ВАЖНО:
не нужно сразу делать все здания.
Первый практический прототип должен доказать сам принцип хотя бы на ОДНОМ здании.
После этого масштабируем модель на остальные.

7. Две главные задачи Vision
Задача №1 — интерактивные здания.
Научиться работать со зданиями как с реальными промышленными/функциональными объектами системы.
Минимальный proof-of-concept:
одно здание →
отдельный PNG →
hover →
информационное окно →
click →
функциональная панель.
После успешного прототипа расширяем систему.
Задача №2 — оживление мира.
Не нужна агрессивная AI-анимация.
Нужны маленькие естественные микродвижения:
- птица медленно летит;
- облака очень медленно перемещаются;
- волны слегка движутся;
- окна зданий иногда включаются/выключаются;
- солнце медленно движется;
- корабли медленно курсируют;
- корабль может прийти в порт, постоять и уйти за горизонт;
- позже вместо ушедшего корабля может прийти новый;
- водопады движутся;
- у водопадов появляется пена у основания;
- лёгкие туманные дымки между островами;
- другие небольшие признаки жизни.
Это должно быть именно "мир живёт", а не мультфильм.

16. Непосредственная следующая задача
Мы сейчас НЕ продолжаем разработку Estate.
Сначала нужно подготовить ноутбук к неделе ограниченного трафика.
Пользователь хочет идти по одному инструменту за раз.
Первым делом определить:
- модель ноутбука;
- CPU;
- GPU;
- VRAM;
- RAM;
- свободное место;
- Windows version.
После этого подобрать конкретный offline-pack.
Особенно интересны:
1. ComfyUI + подходящие модели для image work;
2. локальный LLM runtime (вероятно LM Studio или Ollama);
3. подходящая LLM для ноутбука;
4. инструменты для Vision/Estate;
5. Upscayl и другие image utilities.
НЕ скачивать модели вслепую.
Сначала узнать железо ноутбука.
Для определения GPU можно использовать PowerShell:
Get-CimInstance Win32_VideoController |
    Select-Object Name, AdapterRAM, DriverVersion
Для системы:
Get-CimInstance Win32_ComputerSystem |
    Select-Object Manufacturer, Model, TotalPhysicalMemory
После этого продолжать пошагово.
